# 公网节点的自动识别

> 起点是一个很自然的问题：**能不能在启动时从 ip.cn 取公网 IP，跟本机 IP 比一下，
> 一样就自动把 `relay.serve` 设成 true？**
>
> 答案是不能。下面说清为什么，以及换成什么。

---

## 1. 为什么"比对 IP"不能用

### 1.1 它回答的不是要问的问题

我们真正要知道的是「**别人能不能主动连进来**」，
而不是「我的 IP 看起来是不是公网地址」。这两件事经常不一致：

| 情形 | IP 比对会怎么说 | 实际能不能被连入 |
|---|---|---|
| 公网 IP，但运营商封了入站（**国内家宽常态**） | "公网" ✗ | **不能** |
| 公网 IP + DMZ / 端口映射 | "不是公网" ✗ | **能** |
| CGNAT，多人共享一个公网 IP | 常常误判成"公网" ✗ | **不能** |
| 主机直接在公网网段上（VPS） | "公网" ✓ | 能 |

**最危险的是第一行**：判定为公网 → 自动开启中继 → 这台节点**对外宣称自己是一台中继**，
别人把消息发过来，然后一直失败。而且是**安静地失败** —— 没有人会收到"我其实连不上"的提示。

### 1.2 对一个隐私工具来说，每次启动都去问第三方是反向的

- **泄露**：你的 IP、启动时间、使用频率、使用规律，全部交给一个商业网站；
- **依赖**：对方挂了 / 被墙 / 变慢 → 启动被拖住；
- **可篡改**：把"不可达"说成"可达"就能让一批节点错误地开启中继服务；
- **示范效应**：它教会用户"这个工具启动时会联网上报"。

### 1.3 自动开启 `serve` 本身也需要谨慎

成为中继意味着**陌生人的流量经过你的机器**、消耗你的上行带宽。这应该是
**用户明确同意的选择**，而不是程序根据一个猜测替你决定。规划 §9.2 也要求容量与内容类型可配置。

---

## 2. 更好的办法：分层取证

核心原则：**不要从 IP 分类去推断可达性，要去测量它。**

| 层 | 手段 | 成本 | 能得到什么 |
|---|---|---|---|
| **L1** | 本地网卡地址分类 | 离线、瞬时 | **可靠的否定结论**："只有私网/CGNAT 地址 → 一定连不进来" |
| **L2** | 中继观察到的来源地址 | 零额外泄露（复用打洞那次探测） | 你在 NAT 后面吗？观察到的地址是不是就是你的网卡地址？ |
| **L3** | **入站实证**：请一台中继真的连回来一次 | 一次往返 | **唯一的真凭实据** |

### 2.1 L1：本地地址分类

`classifyInterfaces()` 把每块网卡的地址分成：
回环 / 链路本地 / 私网 / **CGNAT** / 未指定 / 公网。

**CGNAT（100.64.0.0/10）必须单独识别** —— 它不在 RFC1918 里，
漏掉它就会得出"有公网地址"的错误结论，而实际上外面还有一层运营商 NAT。

结论有两种，**只有否定结论是可靠的**：

- `no-public-address` —— 不映射端口就连不进来（可靠）
- `has-public-address` —— 有一个公网地址，**但仍可能被运营商封入站**（不可靠，需 L3）

还有一个细节：**只有公网 IPv6 的机器要单独说明**。
把"有公网 v4"和"有公网 v6"混成一句"有公网地址"会误导用户 ——
纯 IPv4 网络里的对端依然连不进来。

### 2.2 L2：中继观察到的来源地址

中继能看到你的来源地址。这里有两个判据：

- **观察到的地址就在你的网卡列表里** → 数据包没被翻译，你直接挂在公网上（`likely`）
- **不在** → 中间有 NAT 在改写地址（`behind-nat`）

这一步**不需要任何新的外部服务** —— 打洞用的那次 STUN 探测已经拿到答案了。
这比问 ip.cn 更好的地方在于：中继是你**已经选择要使用**的节点，没有引入新的信任方，
也没有新的泄露面。

### 2.3 L3：入站实证（唯一判据）

让一台中继**真的连回来**：

```
客户端 ──REACH_PROBE{我的地址}──► 中继
中继 ──真的去 connect()──► 客户端
中继 ──REACH_RESULT{ok, 实际应答者}──► 客户端
```

**`ok` 的判据是"握手完成且对端身份正是请求方"，不是"TCP 连上了"。**
一个碰巧开着的端口不是可达的证据 —— 测试里专门验证了这条：
连到一个真实存在但身份不符的节点，必须判 `identity-mismatch` 而不是成功。

### 2.4 ⚠️ 必须有的安全闸门：它会变成一个端口扫描器

"请中继去连某个地址"这个接口，如果不加限制就是**端口扫描 / SSRF 原语**：
任何登记过的对端都能让中继去连 `192.168.x.x`、`127.0.0.1`、
或者云上的元数据地址 `169.254.169.254`，把中继当成跳板来探测内网。

所以：

```
isProbeableAddress(address)  →  只有全球可路由地址才允许
内网 / 回环 / 链路本地 / CGNAT / 保留段   一律拒绝
```

再加每分钟 5 次的速率限制 —— 实证要真的建立一个连接，不能变成免费的扫描配额。

实测：

```
中继拒绝了指向内网/元数据地址的实证请求（累计拒绝 1 次）
中继真的去连了一次公网地址并如实回报失败：probe-timeout
实证判据：身份匹配 → 成功；端口通但身份不符 → 失败；连不上 → 失败并带原因
```

## 3. 最终判定：L3 压倒一切

```
有入站实证           → PROVEN       （唯一可以对外宣称的状态）
中继看到的就是本机地址 → LIKELY       （看起来在公网，仍需实证）
观察到的地址不在本机   → BEHIND_NAT
全是私网地址          → PRIVATE_ONLY
数据不足             → UNKNOWN
```

`PROVEN` **压过所有推断**：即使 L1 说"只有私网地址"，只要真的有人连进来过
（比如路由器做了端口映射），就是可达的。

反过来，**没有实证就不冒充可达**。这条直接决定了建议逻辑：

```js
shouldSuggestServing()
  PROVEN  → 建议开启中继
  LIKELY  → **不建议**，理由：needs-inbound-proof
             "看起来直接挂在公网上，但还没有任何节点成功连入过。"
```

## 4. 配置：`serve: 'auto'`

```yaml
relay:
  serve: false    # 不提供（默认）
  # true          # 总是提供（在 NAT 后面打开是没用的）
  # 'auto'        # 只有**实测到有人成功连入过**才提供
```

`'auto'` 的判据只有一条：真的有人连进来过。
**不是**"检测到公网 IP 就开" —— 那样会对外宣称一台谁也用不了的中继。

对外通告里带的是**实证结果**而不是配置值：

```js
relay: { serve: true, verified: <是否 PROVEN>, state: <判定状态> }
```

## 5. 界面

**节点 → 我能不能被别人连上**：

- 结论（用中文说清"这意味着什么"，不是只显示状态名）
- 本机地址分类结果
- 中继观察点数量
- **有人主动连入过几次**（这是唯一有意义的数字）
- 是否对外提供中继

已经配置为提供服务但从未有人连入时，会显示一条醒目的警告：
**"对外宣称可达会让他们白发消息。"**

## 6. 还有什么可以做得更好

| 想法 | 评价 |
|---|---|
| 用多个中继交叉验证来源地址 | ✅ 已经在做（多个观察点才能区分锥形与对称） |
| 用 STUN 协议问公共 STUN 服务器 | 🟡 可行，但仍引入外部依赖；现有中继就是天然 STUN |
| 用 UPnP / NAT-PMP 让路由器自动开端口 | 🟡 **值得做**。这能把 `BEHIND_NAT` 变成 `PROVEN`，而且不需要用户手工配置。安全性上要用户明确同意 |
| 用 ip.cn 之类做**可选的**兜底（无中继时） | 🟡 可以，但必须：默认关闭、明确告知、多个源交叉验证 |
| 反向连接（请对端连我）而非用中继 | ✅ 效果一样，实现上中继最省事 |
| 让 DHT / 引导节点也能做实证 | ✅ 中继只是"能提供实证的一方"，接口是通用的 |

**下一步最值得做的是 UPnP/NAT-PMP** —— 它是唯一能让"我知道自己不可达"变成"我变得可达"的手段，
而其余办法都只能如实报告现状。

## 7. 测试覆盖（24 项）

| 组 | 项数 | 覆盖 |
|---|---|---|
| L1 地址分类 | 9 | 私网/CGNAT/链路本地/回环、**172.16/12 与 100.64/10 的边界**、保留段、非法输入、IPv6 带 zone id、只有 v6 时要单独说明 |
| L2 中继观察 | 5 | 无观察报 unknown、观察到本机地址→likely、观察到别的地址→behind-nat、同内网、**元数据最小化**（不在结论里回显对端地址） |
| L3 入站实证 | 2 | 有实证→PROVEN 且压过推断、无实证不冒充 |
| 建议逻辑 | 3 | 只有实证才建议、已服务不重复建议、NAT 后不建议 |
| 安全闸门 | 4 | 只允许公网地址（含云元数据地址）、中继拒绝探测内网、中继对公网地址真的去连并如实回报、**身份匹配判据** |

## 8. 过程中修掉的问题

| # | 问题 | 说明 |
|---|---|---|
| 1 | 两套并行的可达性状态 | 早期的散落计数器与后来的 `ReachabilityMonitor` 各记一份 —— **同一件事有两个地方记，迟早不一致，而且不一致时没人知道该信哪个**。已统一到监控器 |
| 2 | 嵌套三元表达式写错导致整个模块语法错误 | 五种情况的判定挤在一个嵌套三元里。已改成平铺的 if/else —— 可读性和可改性都更好 |
| 3 | 只有公网 IPv6 却提示"有公网 IPv4" | 文案与事实不符会直接误导用户判断 |
| 4 | `shouldSuggestServing` 不接受注入的网卡信息 | 只能拿真实网卡跑，写不出确定性用例 |
| 5 | 实证的成功判据一度只测"TCP 连上了" | 会把任意一个开着的端口当成可达证据。已改为**必须身份匹配**，并为此把 `probeInbound` 暴露成可单独测试的接口（**闸门归闸门，判据归判据**） |
